## Design Specificity Verdict

**LLM assessment**: This is a _strongly authored_ product, not generic SaaS. Concrete signals: severity reserved as the only saturated palette (with explicit do-not-use-for-chrome guardrails); the four-column Kanban derived from `state + severity`; the Operator-named key journey (Rahim) drives concrete UI choices like the UNSAFE sticky banner having no Acknowledge button because `UNSAFE → acknowledge` is a 409 in the state machine (anti-generic); per-metric display precision; Bengali locale registered though v1 ships English; audit-timeline prose dispatchers enforce Story 4.5's voice in code.

**Three places it leaks generic-SaaS**:

1. **`IncidentDetailActions.tsx` lines 169, 254, 357, 460** use raw `border-slate-900 bg-slate-900 hover:bg-slate-700 disabled:bg-slate-400` — Tailwind defaults, not project tokens. **This is the visible fingerprint of someone copying shadcn snippets.**
2. **`ThresholdsPopulatedView.tsx` + `ThresholdsModals.tsx`** use `borderColor: "#E2E8F0"`, `backgroundColor: "#0F172A"`, `color: "#FFFFFF"` as inline styles — DESIGN.md tokens shipped as hex strings instead of `bg-neutral-border`, `bg-neutral-body`, etc.
3. **`DisabledBanner.tsx` lines 9-12** ship `#FFF7ED / #FDBA74 / #7C2D12` — a parallel warm-warning palette that does not exist in `tailwind.config.ts`. `ConnectionStateBanner` already handles "Reconnecting" using the project's `bg-severity-warning-bg/text` triplet.

**Deterministic scan**: Detector returned 7 raw findings, **100% covered by `ignoreValues`** (severity-driven `border-l-N` accent stripes). With `ignoreValues` applied, the project is **clean by detector**. Browser-visualization step skipped — no browser automation tool exposed in this session; documented honestly, not silently.

**Cross-check**: The detector confirmed three categories the LLM surfaced:

- **Inline-hex token bypasses** (13 sites across `ThresholdsModals`, `ThresholdsPopulatedView`, `ThresholdsPage`, `SimulatorPage`, `RbacDenied`, `NotFound`, `LoginShell`, `FormField`, `Sidebar`, `IncidentDetailPage`, `KanbanCard`) — none hit by detector (it doesn't pattern-match `style={{backgroundColor: '#xxx'}}`), all confirmed by file inspection.
- **Tailwind JIT scanner misses** — `MapView.tsx:94` (`h-[${PIN_SIZE_PX}px] w-[${PIN_SIZE_PX}px]` for the Leaflet pin) and `Sidebar.tsx:61` (`text-[${SIDEBAR_TEXT}]` for inactive nav links) build class names via template-literal interpolation; no matching literal exists anywhere in `src/`, so Tailwind 3.4 does not generate those utilities. **Production map pins and sidebar inactive links render at default browser size/colour.**

The global CSS rule covers default buttons but explicit `h-N w-N` smaller than 44 overrides it.

## Overall Impression

The product is operationally honest, domain-shaped, and almost surgical in its RBAC + audit-timeline care — but the **shadcn lie** is leaking. `package.json`'s description and `DESIGN.md`'s `ui_system: shadcn/ui + Tailwind CSS` both claim a UI system that isn't installed. The codebase does use `clsx` and `tailwind-merge` (the foundation shadcn expects), but **zero** Radix primitives, **zero** CVA, **zero** lucide-react. The visible artifact is the slate-coloured buttons in `IncidentDetailActions` — which is what every shadcn-button-snippet looks like. A reviewer landing on that file will assume the rest of the project uses shadcn; they will be wrong.

The single biggest opportunity is to **make the token system actually be the token system**. Either (a) embrace shadcn — install `@radix-ui/*`, `class-variance-authority`, `lucide-react`, copy in the primitives the codebase needs (Dialog, Dropdown, Toast, Tooltip, Select), and refactor `IncidentDetailActions` + the toast region + the device-row Switch scenario picker on top; or (b) declare "hand-rolled Tailwind utilities on a strict token system" in DESIGN.md, delete the shadcn references from `package.json` and `_bmad-output/.../DESIGN.md`, and run a literal-sweep through every component to remove the remaining slate + inline-hex + warm-warning sites. **Path (b) is the lower-risk, lower-blast-radius move** and it's mostly mechanical work.

## What's Working

1. **Severity token discipline** is a textbook example of "severity carries the design language, not chrome." Every saturated hue in the codebase is reserved for _status meaning only_; dark-mode inversion is computed through CSS custom properties at `:root`; all three pulse keyframes disable under `prefers-reduced-motion`. The Operator scanning a dashboard gets the right signal at the right weight, and a colourblind reviewer still gets it via glyph + label redundancy.
2. **RBAC denial is layered and humane** — route-level `<RbacRoute>` first, then page-level tagged errors (`KanbanRbacDeniedError`, `AdminNotificationsRbacDeniedError`, `IncidentDetailRbacDeniedError`) fall back to `<RbacDenied />` mid-session. The denied surface is calm, factually worded, and announces via `role="status" aria-live="polite"`. 403s betray most products; Surakkha handles them with surgical care.
3. **Audit-timeline language is operator-first prose, not raw JSON.** `formatTimelineEventSummary` (6 dispatchers in `IncidentDetailPage.tsx:181-231`) renders every event type as a calm, factual sentence ("Assigned to [tech-id] by [actor]", "Rejected: [attempted] from [state] is not a valid transition"). Story 4.5's voice is _enforced in code_.

## Priority Issues

### P0 — The "shadcn lie"

DESIGN.md + `package.json` claim shadcn/ui is the UI system; no shadcn deps are installed; the only visible artifact is `IncidentDetailActions` slate buttons.

- **Why it matters**: A new contributor searching for "Surakkha's button pattern" will find `IncidentDetailActions.tsx` and assume the project is shadcn-based. They will be wrong, and the rest of the design system will not make sense to them. DESIGN.md is _binding_ (per CONTRIBUTING.md).
- **Fix (concrete)**:
  - **Path A (adopt shadcn)** — install `@radix-ui/react-dialog`, `@radix-ui/react-dropdown-menu`, `@radix-ui/react-popover`, `@radix-ui/react-tooltip`, `@radix-ui/react-tabs`, `@radix-ui/react-select`, `@radix-ui/react-toast`, `class-variance-authority`, `lucide-react`, `tailwindcss-animate`, `sonner`. Create `components.json` + `src/lib/utils.ts` (`cn()` helper). Copy in the primitives. Refactor `IncidentDetailActions`, the `ToastRegion`, the `NotificationBell` dropdown, the `DeviceRow` scenario picker.
  - **Path B (declare hand-rolled)** — delete `shadcn/ui` from `_bmad-output/.../DESIGN.md` stack list and from `packages/web/package.json` description. Rewrite DESIGN.md §Stack. Run a literal-sweep (one PR) to replace every slate token and every inline hex with a token equivalent.
- **Suggested command**: `/impeccable shape packages/web` (Path A story card) or `/impeccable simplify` on the slate/hex files (Path B).

### P0 — Token discipline is split-brain

`IncidentDetailActions` uses raw `border-slate-900 bg-slate-900 hover:bg-slate-700 disabled:bg-slate-400` on every action button (the codebase has no slate token). Six other files ship inline `style={{ backgroundColor: '#xxx' }}` hex strings.

- **Why it matters**: This single file makes the design system _look_ like shadcn. Two parallel ways to express the same colour, and they disagree.
- **Fix**: Replace with `bg-primary hover:bg-primary-hover disabled:bg-primary/60 disabled:cursor-not-allowed` — exactly the pattern `LoginShell.tsx:206` already uses. Replace inline hex with `className="bg-neutral-surface border border-neutral-border"` etc.
- **Suggested command**: `/impeccable simplify` (single file or batched).

### P1 — Tailwind JIT scanner misses break production visuals

`MapView.tsx:94` (`h-[${PIN_SIZE_PX}px] w-[${PIN_SIZE_PX}px]`) and `Sidebar.tsx:61` (`text-[${SIDEBAR_TEXT}]`) build class names via template-literal interpolation; no matching literal exists in `src/`.

- **Why it matters**: Map pins render at default browser size (16-24 px) instead of the 14 px spec; sidebar inactive links render at default browser colour instead of `#CBD5E1`. Both are silent regressions on a dashboard the Operator sees every day.
- **Fix**: Replace with literal class names; use `text-neutral-sidebar-text` for the sidebar (already a token).
- **Suggested command**: `/impeccable simplify packages/web/src/dashboard/MapView.tsx packages/web/src/shell/Sidebar.tsx`.

### P1 — Three 44×44 touch-target violations remain

`NotificationBell.tsx:357` (disabled Viewer bell) + `:497` (active bell) + `TopBar.tsx:48` (mobile hamburger) all use `h-9 w-9` (36×36 px).

- **Why it matters**: WCAG 2.5.5 floor; mobile / tablet Operator access; global CSS rule doesn't cover these because they override with explicit fixed sizing.
- **Fix**: Bump to `h-11 w-11` (44×44), or add `min-h-touch min-w-touch` (token already exists at `tailwind.config.ts:178-180`).
- **Suggested command**: `/impeccable adapt packages/web/src/notifications/NotificationBell.tsx packages/web/src/shell/TopBar.tsx`.

### P2 — AdminNotificationsPage "Custom" button is disabled but lacks a11y linkage

Visibly disabled `custom` button has no `aria-disabled` + `aria-describedby`; tooltip only appears on hover.

- **Why it matters**: The page is for Admins triaging the audit log — exactly the persona that needs the deepest filter. A "no, that one doesn't work yet" affordance without screen-reader announcement wastes time and confidence.
- **Fix**: Either remove `custom` from `DATE_RANGE_PRESETS` until the follow-up story ships, or render it as `<span aria-disabled="true" aria-describedby="custom-coming-soon">Custom — coming soon</span>` with an inline description element.
- **Suggested command**: `/impeccable simplify packages/web/src/admin-notifications/AdminNotificationsPage.tsx`.

### P2 — Audit timeline surfaces raw 8-char actor UUIDs

`formatActorOrAnonymous` in `IncidentDetailPage.tsx:112` shows raw UUID when actor is known.

- **Why it matters**: "Assigned to f4a1c2b3 by 7d8e9f0a..." reads as noise to the Operator. Story 5.x has user display names available in seed data.
- **Fix**: Show "by an Operator" / "by an Admin" / "by an Technician" when the role is known; reserve the UUID for the rare case the role is genuinely unknown.
- **Suggested command**: `/impeccable clarify packages/web/src/incidents/IncidentDetailPage.tsx`.
