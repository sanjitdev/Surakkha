- (event) Source scan completed; awaiting user confirmation of source set before extraction.
- (decision) Use docs/Surakkha-PRD.md, docs/Surakkha-BRD.md, docs/architecture.md, and docs/Surakkha-idea-refined.md as the authoritative source set for the UX design.
- (decision) Primary form factor: responsive web-first (designed for laptop and tablet, usable on smaller phones).
- (decision) Visual direction: operational serious — clean, restrained, high-information-density, trustworthy water-safety operations dashboard.
- (decision) Primary key-journey protagonist: Rahim, Operator — the named Operator who sees a TDS breach, acknowledges the alert, assigns a Technician, follows the incident to resolution, and audits the outcome.
- (decision) Severity palette: operational traffic light — green/amber/red severity coloring with accessible contrast for healthy / warning / critical readings, alerts, and incidents.
- (decision) Typography stack: Inter (variable) primary for Latin script, Noto Sans Bengali fallback for future bn locale; Tailwind fontFamily tokens registered now to keep v2 a content drop.
- (decision) Information density: comfortable by default — generous spacing and larger touch targets, prioritizing legibility on low-end devices over fitting many metrics per screen.
- (decision) Primary navigation: left sidebar with role-aware items; collapses to a hamburger trigger on viewports under ~1024px.
- (decision) Live updates: soft pulse — charts and KPI values silently update; status changes tint the affected card with a 1.2s outline glow; no toasts on routine readings.
- (decision) Offline UX: read-only last-known state — the dashboard continues to render its last-known data, a top-of-page 'Reconnecting…' banner is shown, and any action that would hit the API is disabled with a tooltip explaining why.
- (decision) Critical banner: persistent red top-of-page banner across all routes for Admin sessions when an UNSAFE result is submitted; shows device and acknowledge CTA; dismisses on acknowledgement or after 24 hours.
- (decision) Accessibility floor: WCAG 2.1 AA with full keyboard reachability — keyboard navigation on every interactive element, visible focus rings, semantic HTML, ARIA where required, 4.5:1 minimum text contrast, severity also conveyed through text/icon (never color alone). No explicit screen-reader certification target.
- (decision) Voice and tone: calm, factual, brief — short sentences, no exclamation marks, no marketing copy; examples include 'TDS is 312 ppm. Threshold is 300 ppm.' and 'Acknowledged at 10:42 by Rahim.'
- (decision) Dashboard layout: KPI band on top, full-width map below, then live readings table, then recent incidents feed — matches the PRD F-7 ASCII wireframe.
- (decision) Comprehension beats: animated walk-through on first login (auto-dismiss after one cycle); a permanent legend strip on the dashboard shows Healthy/Warning/Critical color meanings; no always-visible incident rail — the main canvas stays clean.
- (decision) Working mode: coaching — decisions are pulled out one at a time; remaining open questions and key flows will be elicited before distillation.
- (decision) Kanban shape: native five-column Kanban at /incidents — OPEN, ACKNOWLEDGED, INSPECTING, AWAITING REVIEW, RESOLVED. Cards show id, severity, age, and assignee. Technician view is filtered to assigned incidents.
- (decision) Chart layout: combined Recharts chart per sensor with toggleable metric series and threshold reference lines; chosen for comfortable density and readability.
- (decision) Map: Leaflet markers colored by severity; click reveals a popup with device label, latest reading, and a link to /sensors/:id.
- (decision) Theming: light and dark themes both ship in v1, defaulting to the user's system preference; no manual toggle in v1 (deferred to v2).
- (decision) Key journey climax: safety beat — Rahim takes the incident from OPEN through to RESOLVED; the climax is the moment the Critical banner clears after the Operator reviews and closes the incident.
- (decision) Role-aware navigation: sidebar items are entirely hidden when the user lacks permission (disabled-with-tooltip is a v2 polish).
- (decision) Notification model: bell-icon dropdown for routine notifications, persistent red Critical banner for UNSAFE, and /admin/notifications lists every recorded notification.
- (decision) Key-screen mocks: Executive dashboard, Incident detail with Critical banner, Admin simulator, Login, Sensor detail, and Incident Kanban. These cover the demo flow, role-aware navigation, and the 60-second comprehension target.
- (decision) Reviewer Gate: run the full review — rubric walker plus structure and prose lenses; resolve findings before finalization.
