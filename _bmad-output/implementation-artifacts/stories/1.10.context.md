# Story 1.10 — Single-Secret JWT Rotation Policy (context)

**Status:** in-progress (this commit)
**Covers:** FR-25, I-13
**Source:** `_bmad-output/planning-artifacts/epics.md` lines 612–634

## Intent

Story 1.4 shipped HS256 + a single `JWT_SECRET` with a fail-fast
guard. Story 1.10 is the *policy* half: no future contributor should
confuse "single secret" with "rotation-ready". The constraint is
pinned three ways:

1. **README** — the JWT section names the contract verbatim and links
   to `docs/architecture-appendix-opconstraints.md` (I-13).
2. **Invariant test** — `__tests__/auth.no-rotation.spec.ts` reads the
   api source and asserts no `JWT_PUBLIC_KEY` env var is referenced
   anywhere in the api package.
3. **PR rule** — the same test is mirrored in CI as a gate; a PR that
   adds JWKS support will fail the test and the PR description must
   include a v2-bump justification to land the change.
