# Story 1.7 — 401 Refresh Flow (context)

**Status:** shipped (commit `8742339`, 2026-08-21)
**Covers:** UX-DR-12
**Source:** `_bmad-output/planning-artifacts/epics.md` lines 527–555

## Intent

A short-lived access token rotation does not interrupt the user. A
genuine session loss redirects to `/login?next=<current-path>` without
losing the target URL. A socket-side `401 token_expired` reconnect
uses the freshly minted token. A network error during refresh surfaces
the offline state without logging the user out.

## Acceptance criteria — file mapping

| AC bullet (epics.md) | Satisfaction |
|---|---|
| 401 on `/dashboard` → `POST /auth/refresh` once via httpOnly cookie | `api/apiClient.ts` `apiFetch` |
| Original request retried exactly once with new token | `api/apiClient.ts` `retryAfterRefresh` |
| Refresh also 401 → redirect `/login?next=/dashboard` | `api/apiClient.ts` AC2 branch |
| After login, SPA navigates back to `/dashboard` | `main.tsx` `?next=` handling |
| Socket `401 token_expired` → reconnects with fresh token | `realtime/socketClient.ts` `connect_error` + `SOCKET_TOKEN_EXPIRED` |
| UI does not unmount or flash a loading screen | `realtime/socketClient.ts` `reconnectWithToken` |
| Network error during refresh → offline state, no logout | `api/apiClient.ts` AC4 branch + `onOffline` |
| Interceptor does not retry refresh more than once per API call | `api/apiClient.ts` `inflightRefresh` coalescing |
