# Story 1.5 — RBAC Middleware (context)

**Status:** shipped (commit `e272f95`, 2026-08-21)
**Covers:** FR-20, AR-10
**Source:** `_bmad-output/planning-artifacts/epics.md` lines 474–500

## Intent

A single `authorize.ts` middleware runs after auth and before every
handler. Every protected endpoint enforces `(subject, action, resource)`
and the audit row for a denial is written through one place.

## Acceptance criteria — file mapping

| AC bullet (epics.md) | Satisfaction |
|---|---|
| Authenticated user with role Operator calling an Admin endpoint → `403 forbidden` with `{ error: "forbidden", required_role: "Admin" }` | `middleware/authorize.ts` `authorize()` |
| `AuditLog` row written with `actor_user_id`, `action`, `resource`, `outcome: "denied"` | `audit.ts` + `authorize.spec.ts` |
| Matrix-allow cell → `next()` and handler runs | `authorize.ts` matrix lookup |
| No access token → `401 unauthorized`; handler does not run | `authorize.ts` `authenticate` |
| Role/action/resource predicates come from `packages/shared/src/rbac.ts` only | `authorize.ts` imports |
| `// PUBLIC` comment is the only bypass; CI-lint-checked | `authorize.ts` + `scripts/lint-rbac-matrix.mjs` |
