# Story 1.4 — JWT Auth + Refresh (context)

**Status:** shipped (commit `8184cda`, 2026-08-21)
**Covers:** FR-22, FR-23, FR-24, FR-25, AR-4
**Source:** `_bmad-output/planning-artifacts/epics.md` lines 434–472

## Intent

A user signs in once and the platform issues an access token + a
refresh token. The session survives short-lived access expiry without
re-entering the password. The api is fail-fast on a weak JWT secret
(FR-25 / I-13).

## Acceptance criteria — file mapping

| AC bullet (epics.md) | Satisfaction |
|---|---|
| `/auth/login` response: `{ access_token }` HS256, 8-hour expiry, `iss: surakkha-api`, `aud: device` | `auth/router.ts` + `auth/jwt.ts` (`issueAccessToken`) |
| `refresh_token` httpOnly cookie scoped to API origin, `SameSite=Strict` | `auth/router.ts` cookie config |
| Unknown email / wrong password → `401 unauthorized` with `{ error: "invalid_credentials" }` | `auth/router.ts` |
| No audit entry on a wrong-password failure | `auth/router.ts` (no emit on failure) |
| Valid access token within 8h → endpoint accepts | `auth/jwt.ts` `verifyAccessToken` |
| Token's `aud` claim matches the endpoint's expected audience | `auth/jwt.ts` `aud` verification |
| Within 60s of expiry → TanStack Query interceptor refreshes (Story 1.7) | `api/apiClient.ts` (Story 1.7) |
| password column is bcrypt cost 12 | `auth/users.ts` (`hashPassword`) |
| Plaintext password never logged | `auth/router.ts` (no `console.log` of password) |
| `JWT_SECRET` missing/empty/<32 chars → process.exit(1), no routes registered | `auth/jwt.ts` fail-fast check + `auth/router.ts` gate |
