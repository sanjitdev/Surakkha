# Story 1.8 — Negative RBAC Tests (context)

**Status:** shipped (commit `4a4ee53`, 2026-08-21)
**Covers:** FR-21
**Source:** `_bmad-output/planning-artifacts/epics.md` lines 557–585

## Intent

A data-driven negative test register pins the (subject, action,
resource) → 403 contract every later handler must honour. Refactors
cannot silently re-introduce role bypass because the test register
fails first.

## Acceptance criteria — file mapping

| AC bullet (epics.md) | Satisfaction |
|---|---|
| Operator GET /audit → 403 with `{ required_role: "Admin" }` | `NEGATIVE_CASES` #1 |
| Operator GET /audit → audit entry written | `rbac_denied` event in audit capture |
| Viewer POST /incidents → 403 | `NEGATIVE_CASES` #2 |
| Viewer POST /incidents → no Incident row created | handler does not run |
| Technician GET /incidents/{id} for an incident assigned to another user → 403 | cross-cutting ownership case |
| Technician does not see the other-user incident in `/incidents` list | (matrix-level deny + ownership check) |
| At least 10 negative RBAC cases pass | 14 cases in `NEGATIVE_CASES` + 2 ownership cases |
| Test file namespaced `__tests__/rbac.negative.spec.ts` | `packages/api/__tests__/rbac.negative.spec.ts` |
