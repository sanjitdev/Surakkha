# Story 1.3 — Login Shell (context)

**Status:** shipped (commit `a8ec5ec`, 2026-08-21)
**Covers:** PRD F-5; UX-DR-4 (login portion)
**Source:** `_bmad-output/planning-artifacts/epics.md` lines 405–432

## Intent

A user signing in sees a calm, split-screen login screen with a
gradient hero and a sign-in form. The login shell is the first
authenticated-state surface, so it must inherit the design system
established in Story 1.2a/b.

## Acceptance criteria — file mapping

| AC bullet (epics.md) | Satisfaction |
|---|---|
| ≥1024px `/login`: left half = primary gradient hero + brand mark + tagline | `LoginShell.tsx` |
| ≥1024px `/login`: right half = email + password fields + "Sign in" button | `LoginShell.tsx` + `FormField.tsx` |
| <1024px: gradient hero is hidden | `LoginShell.tsx` responsive guard |
| <1024px: form fills viewport width with 24/16/12 canvas padding per breakpoint | `LoginShell.tsx` + `index.css` |
| Submit POSTs to `/auth/login` (wired in Story 1.4) | `LoginShell.tsx` `handleSubmit` |
| Button disabled with label "Signing in…" while in-flight | `LoginShell.tsx` state machine |
| No string contains `!` and no marketing language | `login.spec.tsx` + manual review |
