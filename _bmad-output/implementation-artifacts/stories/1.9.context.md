# Story 1.9 — Critical-First Visual Hierarchy on the Login Shell (context)

**Status:** in-progress (this commit)
**Covers:** UX-DR-2, UX-DR-6
**Source:** `_bmad-output/planning-artifacts/epics.md` lines 587–610

## Intent

A reviewer authenticates and lands on the authenticated shell. The
shell must visibly demonstrate that the saturated severity palette
(Story 1.2a) and the motion tokens (DESIGN.md §Layout & Spacing) are
*rendered* — not just defined in `tailwind.config.ts`. Story 1.9 is
the "show the design system inheritance" story: a sample `KpiStat`
card uses the registered `value/text/fill/bg/glow` tokens, the
critical KPI numeral is 44px (40px for non-critical) with a 4px solid
critical left border, and the critical pulse runs at 1500ms.

## Acceptance criteria — file mapping

| AC bullet (epics.md) | Satisfaction |
|---|---|
| Sample severity card uses `value`, `text`, `fill`, `bg`, `glow` from registered tokens | `KpiStat` component consumes `severity.<sev>.<cell>` from `tailwind.config.ts` |
| Card border, KPI stripe, shadow all resolve to `critical` | `KpiStat` critical variant uses `border-severity-critical-value`, `shadow-elevation-card` + critical glow |
| Critical KPI numeral font-size 44px (40px for non-critical) | `fontSize["kpi-numeral"]` = 40px, `fontSize["kpi-numeral-critical"]` = 44px in `tailwind.config.ts` |
| Left border 4px solid using critical `value` token | `KpiStat` critical variant: `border-l-4 border-severity-critical-value` |
| Critical pulse animation runs at `motion.critical_pulse_ms 1500` | `.animate-critical-pulse` (already in `index.css`, 1500ms) applied to critical card |
| Healthy state shows no continuous animation (only transient live-update glow) | Healthy variant applies no `animate-critical-pulse` |
