# Story 1.6 — Role-Aware Nav + RBAC Denied State (context)

**Status:** shipped (commit `034634e`, 2026-08-21)
**Covers:** FR-21, UX-DR-13
**Source:** `_bmad-output/planning-artifacts/epics.md` lines 502–525

## Intent

The sidebar shows only the nav items the active role has permission to
use. A direct-navigate to a forbidden route shows a calm explanation
with a link back to `/dashboard`.

## Acceptance criteria — file mapping

| AC bullet (epics.md) | Satisfaction |
|---|---|
| Viewer: items requiring Operator/Admin are not rendered in the DOM | `shell/nav.ts` `filterNavByRole` + `Sidebar.tsx` |
| Viewer: items the Viewer can access are rendered | same |
| Operator types `/audit` → empty state "You don't have access to this page. Contact an Admin." | `access/RbacDenied.tsx` |
| Empty state contains a link back to `/dashboard` | `RbacDenied.tsx` |
| RbacDenied uses semantic HTML (`<main>`, `<h1>`) and `role="status"` | `RbacDenied.tsx` |
| Page is keyboard-reachable with a visible focus ring | `RbacDenied.tsx` + `--focus` token |
