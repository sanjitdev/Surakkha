## From Edge Case Hunter (subagent)

**BLOCKER (3):**

- **B-1** — Silent production data loss via metric-vocabulary mismatch. Raw `Reading.metrics` uses `TelemetryMetrics` long names (`tds_ppm`, `turbidity_ntu`, `temp_c`); `ReadingAggregateMetric` is short names (`tds`, `turbidity`, `temperature`). Cron's `rawMetrics[metric]` lookup returns undefined → `typeof !== "number"` guard → silent continue → 0 upserts → audit emits `success` with `aggregatedRows: 0`. Raw rows ARE deleted by the trailing `deleteMany`, so this is data loss. Test rig masks it by emitting both vocabularies.
- **B-2** — Lock-acquire query throw → no `finally` → lock leaked if DB drops connection between `pg_try_advisory_lock` returning `true` and our JS code observing the response. Wrap the acquire in its own `try/finally`.
- **B-3** — No `MAX_BATCHES` ceiling + no `batchSize > 0` runtime guard. Misconfigured `batchSize` (NaN, Infinity, "10000" string) → infinite loop.

- H-3 — Migration has no `IF NOT EXISTS`; re-running `prisma migrate dev` against an already-applied DB detects drift → `migrate reset` prompt destroys prod data.
- H-4 — DST refactor hazard (current code is correct; future switch to `setDate` would break).
- H-5 — `scheduleRetentionCron` accepts `batchSize: 0` directly (bypassing `RetentionConfigSchema`); runtime guard needed.
